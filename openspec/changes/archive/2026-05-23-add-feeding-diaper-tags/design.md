## Context

手机端每日回顾已经支持为时间段分配标签、展示稳定颜色、按标签筛选列表，并保留自定义标签能力。当前预设标签由手机端 UI 层提供，标签持久化仍以标签文本关联到时间段，不需要为新增预设标签修改标记事件、时间段推导、同步协议或 Room schema。

本次变更只扩展预设标签集合：加入“喂奶”和“换尿布”，让婴儿照护场景可以直接选择和筛选。

## Goals / Non-Goals

**Goals:**

- 在时间段标签编辑入口中展示“喂奶”和“换尿布”两个预设标签。
- 为两个新增预设标签提供稳定、可区分的颜色。
- 让两个新增标签参与已有的标签展示和筛选流程。

**Non-Goals:**

- 不新增标签管理页面。
- 不改变标签存储结构或时间段身份计算方式。
- 不在手表端增加标签选择。
- 不改变已有预设标签、自定义标签或未标记状态语义。

## Decisions

### 只扩展现有预设标签源

在现有手机端预设标签列表中追加“喂奶”和“换尿布”，并沿用当前标签编辑、保存、展示和筛选逻辑。

理由：现有能力已经覆盖时间段标签的完整生命周期，新增标签属于预设集合扩展，不需要引入新的标签模型。

替代方案是新增婴儿照护分类或单独标签类型，但当前需求只有两个具体标签，分类会增加 UI 和状态复杂度。

### 颜色继续作为 UI 层映射

为“喂奶”和“换尿布”补充显式颜色映射，保持与已有预设标签一致；自定义标签仍按现有稳定映射处理。

理由：颜色是展示属性，现有设计已经避免将颜色写入持久化模型。新增两个预设颜色可以让标签 chip 和筛选入口立即具备稳定视觉区分。

替代方案是为预设标签引入持久化元数据，但会带来迁移和重复状态，超出本次范围。

## Risks / Trade-offs

- 新增标签颜色与现有标签过近 -> 选择与现有预设明显区分的颜色，并在标签选择、时间段行和筛选入口保持一致。
- 预设标签顺序影响选择效率 -> 将两个婴儿照护标签放入现有预设列表中，保持顺序稳定，避免筛选栏和编辑入口跳动。
- 仅新增预设不等于自动识别活动 -> 本次明确保持用户手动选择标签，自动推断不在范围内。
