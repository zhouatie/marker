## Context

手机端当前每日回顾界面由一个 `LazyColumn` 串联标题、tab、手表快捷入口说明、地图和时间段列表。这个结构把一次性配置说明放在每日回顾内容前面，也让时间线 tab 与地图 tab 共享同一个小地图组件：时间线 tab 展示“地图 + 列表”，地图 tab 只展示“地图”。结果是主任务不够突出，tab 切换也缺少明确的信息差。

现有规格已经明确：时间线是每日回顾主视图，地图是位置上下文辅助视图。因此本设计只调整手机端 UI 信息架构和视觉交互，不改变数据模型、标记推导、同步协议或地图连接语义。

## Goals / Non-Goals

**Goals:**

- 让时间线 tab 成为纯粹的每日活动回顾视图，优先展示当前日期、当前/最近时间段和时间段列表。
- 让地图 tab 成为独立的空间上下文视图，而不是时间线顶部的重复预览。
- 移除主内容顶部常驻的“手表快捷入口”提示，避免干扰已有记录用户的回顾流程。
- 保留时间线与地图之间的选中联动：用户选择时间段后，地图可以高亮对应标记点和连接线。
- 提升时间段行的可扫描性：时间范围、标签、位置上下文和选中状态要有清晰视觉层级。

**Non-Goals:**

- 不引入真实地图 SDK 或连续 GPS 轨迹。
- 不改变标记事件、时间段标签、Room schema 或同步协议。
- 不改变时间段推导、排序和开放式当前时间段语义。
- 不新增手表端交互，也不改变 Watch7 快捷捕获流程。
- 不实现“已完成 onboarding”持久化状态；本次只定义主界面提示策略和可用展示位置。

## Decisions

### 将时间线和地图拆成互斥主内容

时间线 tab 只展示时间段回顾内容，不再在列表上方展示完整地图。地图 tab 承担完整空间视图，展示所选日期中有坐标的标记点、直线连接、非真实路线说明和所选时间段高亮。

理由：时间线和地图回答的问题不同。时间线回答“我今天按时间做了什么”，地图回答“这些边界点大致发生在哪里”。把地图放在时间线顶部会抢占首屏，也让地图 tab 失去存在意义。

考虑过的替代方案：保留时间线顶部小地图作为 summary。这个方案能提供位置线索，但会继续造成 tab 重复；对于主要回顾流程，时间段列表比地图更重要。

### 将手表快捷入口说明降级为辅助引导

当用户已有时间段或标记时，主回顾内容不再常驻展示“手表快捷入口”说明。该说明可以出现在无标记空状态中，或未来放入设置/帮助入口。

理由：快捷入口配置属于 setup/onboarding，不是每日回顾内容。对已经开始使用的用户，它每次占据顶部空间会降低回顾效率。

考虑过的替代方案：继续常驻显示但缩小视觉权重。这个方案仍然会把一次性说明放在核心内容前面，不能解决信息架构问题。

### 保持单一选中状态跨 tab 复用

继续使用一个所选时间段状态作为时间线行选中和地图高亮的桥梁。用户在时间线 tab 选中时间段后，切到地图 tab 时应看到对应标记点或连接线高亮；用户在地图 tab 选择可关联的标记连接时，也可以更新同一选中状态。

理由：时间线和地图是同一天数据的两种视图，选中上下文应跨视图保留，避免用户切 tab 后丢失关注对象。

考虑过的替代方案：每个 tab 维护独立选中状态。实现更简单，但用户从列表切到地图时无法延续上下文。

### 使用现有 Compose Material 组件完成视觉优化

本次使用已有 Material3、Canvas 和 Compose 布局能力优化视觉层级，不新增图标库、地图 SDK 或复杂导航框架。

理由：当前应用仍是轻量 MVP，主要问题是信息架构和层级，而不是缺少底层地图能力。保持依赖稳定可以降低实现风险。

考虑过的替代方案：直接接入真实地图组件。真实地图能提供更强空间感，但会引入权限、密钥、依赖和渲染复杂度，超出本次 UI 结构优化范围。

## Risks / Trade-offs

- [Risk] 移除时间线顶部地图后，用户可能少看到位置线索 -> Mitigation: 时间段行继续展示简洁位置上下文，并允许用户切到地图 tab 查看完整空间视图。
- [Risk] 无标记用户找不到如何开始记录 -> Mitigation: 空状态保留手表快捷入口指引，主界面仅在已有内容时移除常驻提示。
- [Risk] 地图 tab 如果仍只有 160dp 小画布，会显得不够像独立视图 -> Mitigation: 实现时让地图 tab 使用更大的画布和更完整的说明/状态呈现。
- [Risk] 跨 tab 选中状态可能因为开放式时间段或缺失坐标无法高亮 -> Mitigation: 地图只高亮可定位的标记点；缺坐标时间段仍在时间线保留，并在地图中给出缺少位置的空/说明状态。
- [Risk] 视觉优化可能扩散成大规模重构 -> Mitigation: 修改范围限制在手机端每日回顾 Composable，避免调整数据层和同步层。
