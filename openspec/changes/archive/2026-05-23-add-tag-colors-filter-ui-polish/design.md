## Context

手机端每日回顾页面目前集中在 `MainActivity.kt` 的 Compose UI 中：页面本地状态负责日期、视图切换、选中时间段、标签编辑和标记点管理；`TimelineViewModel` 负责暴露按日期推导后的时间段与保存标签。标签当前是纯字符串，预设标签由 `predefinedLabels()` 提供，自定义标签也允许保存。

本次变更主要是手机端 UI 和交互状态改进，不改变标记同步、时间段推导、标签持久化或删除标记后的标签清理规则。

## Goals / Non-Goals

**Goals:**

- 让同一个标签在时间段行、标签编辑弹窗和筛选栏中使用一致颜色。
- 支持用户按标签筛选时间线列表，包括“全部”和“未标记”。
- 优化每日回顾页面视觉层级，让日期、视图切换、筛选、时间段内容、选中态和空状态更容易扫描。
- 保持时间线 tab 顶部控制固定、列表独立滚动的现有要求。

**Non-Goals:**

- 不新增标签管理页面。
- 不改变标签存储结构，不为标签颜色新增 Room 表或迁移。
- 不改变手表端捕获流程，也不在手表端增加标签选择。
- 不引入新的 UI 框架或外部依赖。

## Decisions

### 使用 UI 层稳定颜色映射

标签颜色通过一个手机端 UI 工具函数从标签文本映射到固定调色板。预设标签可以使用显式颜色表，自定义标签使用文本 hash 选择调色板颜色。

理由：颜色是展示属性，不需要写入持久化模型。这样可以避免 Room schema 迁移，并保证自定义标签在重启后仍然得到稳定颜色。

替代方案是把颜色存到标签记录里，但当前标签记录绑定在时间段上，同一个自定义标签可能重复出现，持久化颜色会增加重复状态和迁移成本。

### 筛选状态保持在手机端页面状态

当前筛选条件使用页面本地 Compose state 维护，默认值为“全部”。当用户切换日期时，筛选条件可以保留；如果筛选后没有结果，页面展示筛选空状态，并允许用户一键回到“全部”。

理由：筛选只是当前回顾页面的视图状态，不影响数据含义，也不需要同步给手表或持久化。

替代方案是放进 `TimelineViewModel`，但目前筛选不涉及仓库查询，也不需要跨进程恢复；在页面层处理更直接。

### 筛选项来自当前日期可见时间段

筛选栏包含“全部”、“未标记”和当前日期时间段中出现过的标签。标签项按预设标签顺序优先展示，再展示自定义标签，避免筛选栏顺序随着列表滚动或数据重组显得随机。

理由：用户是在回顾某一天，筛选项应该反映当天实际存在的内容，减少无效入口。

### UI 美化优先使用 Material3 组件与现有 Compose 结构

页面保持现有 Column + LazyColumn 架构：顶部日期和视图切换区域更紧凑；时间线 tab 在列表上方增加横向/流式标签筛选 chip；时间段行使用更明确的时间、状态、位置、标签、操作区层级；选中态通过边框或柔和背景强调，不挤压内容。

理由：当前应用是工具型每日回顾，不需要营销式大图或复杂装饰。用 Material3 组件收敛视觉层级可以在小屏上更稳定。

## Risks / Trade-offs

- 标签 hash 颜色可能让两个常用自定义标签颜色相近 -> 使用一组对比足够的调色板，并为预设标签指定更明确的颜色。
- 筛选条件保留后切换日期可能出现空结果 -> 空状态明确说明当前筛选无匹配，并提供回到“全部”的操作。
- 时间段行增加视觉元素后可能变拥挤 -> 操作按钮使用图标或短文本，标签 chip 控制最小宽度和换行，避免挤占时间范围。
- 只在 UI 层映射颜色意味着用户不能自定义颜色 -> 本次先解决识别和筛选问题，不引入标签管理复杂度。
