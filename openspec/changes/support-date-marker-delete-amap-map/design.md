## Context

手机端当前以当天时间线为主视图，`selectedDate` 固定为当前日期；地图 tab 使用 Compose Canvas 按坐标范围归一化后绘制标记点和直线。现有规格已经要求地图直线只表达活动边界点之间的连接，不代表真实路线。

这次变更同时触及 UI 状态、标记数据生命周期、同步幂等性和外部地图 SDK。核心约束是：日期切换必须成为时间线和地图共同的上层状态；删除标记必须能防止晚到同步载荷恢复；真实地图不能改变“标记连接线不是轨迹”的产品语义。

## Goals / Non-Goals

**Goals:**

- 支持用户选择日期并查看该日期的时间线和地图。
- 支持从时间段上下文删除误打标记点，并重新推导受影响时间段。
- 接入高德 Android 地图 SDK，用真实底图承载标记点和直线连接。
- 保持时间线和地图之间的选中时间段上下文。
- 明确历史日期的开放式时间段语义，避免历史日期展示“到现在”。

**Non-Goals:**

- 不实现真实轨迹记录、路径规划或导航路线还原。
- 不在手表端增加删除 UI。
- 不迁移被删除标记相关时间段的旧标签到新时间段。
- 不引入高德以外的地图供应商兼容层。

## Decisions

### 日期状态由 ViewModel 管理

`selectedDate` 改为 ViewModel 中的可变状态，并作为时间线列表、地图点位和标题控件的共同输入。UI 顶部保留固定控制区，提供前一天、后一天和日期选择器入口。

备选方案是让时间线 tab 和地图 tab 各自维护日期状态，但这样会导致两个视图在切换时上下文不一致。统一状态更符合当前“时间线/地图共享所选时间段”的规格。

### 历史日期不展示“当前进行中”

只有所选日期是系统当前日期时，最后一个没有结束标记的时间段才展示为开放式当前时间段。历史日期最后一个标记没有后续标记时，展示为未闭合时间段或截止到当天结束的回顾边界，具体文案由 UI 实现决定。

这样可以避免用户回看昨天时看到“昨天某时到现在”的错误语义。

### 标记删除采用软删除墓碑

手机端删除标记时写入删除状态和删除时间，而不是直接物理移除。时间线推导和地图展示过滤已删除标记；同步接收逻辑在遇到旧版本或普通标记载荷时不得恢复已删除标记。

备选方案是物理删除标记，但手表端和晚到载荷仍可能再次投递同一个标记，导致用户删除失效。墓碑记录会增加数据模型复杂度，但能保持幂等性。

### 删除从时间段上下文进入，必须二次确认

时间段行保持点击选中和标签编辑为主要操作；删除入口放在更多菜单或长按后的“管理标记点”底部弹层中。用户可以看到开始点和结束点，并对具体点触发删除。删除前弹出确认，说明删除会重新计算相邻时间段。

这能降低误删概率，也符合“删除的是边界标记，不只是地图上的一个点”的实际语义。

### 被删除标记相关标签不迁移

删除标记后，任何以该标记作为开始或结束边界的时间段标签都不迁移到新生成的时间段。新时间段保持未标记，用户可以重新选择标签。

备选方案是自动保留前一个或后一个标签，但中间点删除后两个时间段语义已经合并，自动继承容易制造错误回顾。

### 地图选用高德 Android 地图 SDK

地图 tab 使用高德 Android 地图 SDK 展示真实底图、Marker 和 Polyline。高德更适合国内 Android 使用场景，并能覆盖本需求需要的点标记、线段绘制和地图视野适配。实现时需要在使用 SDK 前完成隐私合规初始化，并通过本地配置提供 API key。

不引入 Google Maps 或 Mapbox 兼容分支，避免为了未确认使用场景增加兼容性代码。

### 地图线段保持“直线连接”语义

地图按所选日期的时间顺序展示有坐标的标记点，只在相邻标记都存在坐标时绘制直线线段。线段样式应区别于导航路线，并在地图 tab 保留说明文案。

如果所选时间段只有一个端点有坐标，只高亮该端点；如果两个端点都有坐标，则高亮两个端点和对应直线。

## Risks / Trade-offs

- 高德 SDK 增加外部依赖和 API key 配置 -> 使用本地配置读取 key，并在文档中标出必须的隐私初始化与权限。
- 软删除墓碑会让数据库保留已删除记录 -> 查询层统一过滤，后续可单独设计清理策略，但本次不做自动清理。
- 历史日期末尾时间段的结束边界可能有不同产品解释 -> 规格只要求不得展示“当前进行中”，实现可用“未闭合”或当天结束边界表达。
- 删除标记会改变多个时间段 -> 删除确认中明确说明影响，且不自动迁移标签。
- 高德地图在无网络、无 key 或权限不足时不可用 -> 地图 tab 必须提供清晰错误或空态，不影响时间线回顾。

## Migration Plan

1. 数据库新增标记删除状态所需字段或墓碑表，并迁移现有标记为未删除。
2. 更新标记查询、时间线推导输入和地图点位输入，默认过滤已删除标记。
3. 更新同步接收逻辑，使删除墓碑优先级高于旧普通标记载荷。
4. 引入高德地图依赖、key 配置和隐私初始化。
5. 更新 UI 状态和交互：日期选择、标记管理、删除确认、地图承载。

回滚时可以隐藏删除入口和高德地图入口；保留墓碑字段不会影响未删除标记的时间线推导。
